# Deployment artifacts

`initial-inspection-schedule.csv` is generated from `data/forms.json` by running `npm run generate:schedule`. Import it only after the target SharePoint list has a unique indexed `ScheduleKey` text column and the department routing table has been validated.

`sample-audit-report.html` is a deterministic rendering fixture generated by `npm run generate:audit`. It intentionally identifies missing corrective-action and workflow-history inputs and is not a complete regulatory audit package.

The live `QCMS Generate Audit Report` flow (`c534f2d7-8187-4cee-9a5e-b389ca6059f5`) accepts Start Date and End Date inputs, applies those dates to Inspection Records, Inspection Responses, Corrective Actions, and Workflow History queries, paginates all four reads to a 100,000-item threshold, creates an HTML response-detail table, and saves a timestamped artifact to the private `QCMS Reports` SharePoint library. Controlled run `08584176229210326038362205365CU12` generated `QCMS-Audit-2026-06-01-to-2026-07-13-20260713-230616.html` successfully. After adding the two audit sources, controlled run `08584176220107551792178553093CU15` completed in four seconds with zero flow-checker errors or warnings and returned four corrective actions plus four workflow-history events. The live artifact does not yet render those two datasets as normalized HTML sections and must not be treated as the final regulatory package until that presentation and relationship filtering are implemented.
